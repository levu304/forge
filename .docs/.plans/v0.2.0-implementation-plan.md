### Step 2 — Selection Manager

**Goal:** Implement `SelectionManager` with `HashSet<hecs::Entity>`, `Selected` marker component sync, `SelectionMode` enum, and full API (select, deselect, clear, replace, is_empty, count, handle_picking_result).

**Context Brief:**

`SelectionManager` is the canonical selection API. It holds a `HashSet<hecs::Entity>` for O(1) membership. Every `select()` call also inserts a `Selected` marker component into the ECS world; every `deselect()` call removes it. `handle_picking_result(entity)` processes GPU picking results — if entity is `Some`, select it (replace mode); if `None`, clear all.

The spec explicitly requires sync between the HashSet and the ECS marker component. The `primary` field tracks the last-selected entity for the property panel (v0.3.0+). The `mode` field has `Replace` (default), `Add`, `Remove` — only `Replace` is active in v0.2.0; `Add`/`Remove` are for future Ctrl+click.

**Task List:**

1. **Implement `src/selection/mod.rs`:**
   - `SelectionManager` struct with `selected: HashSet<hecs::Entity>`, `primary: Option<hecs::Entity>`, `mode: SelectionMode`
   - `SelectionMode` enum: `Replace` (default), `Add`, `Remove` — with `#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]`
   - `impl SelectionManager`:
     - `select(&mut self, world: &mut World, entity: Entity)` — insert in set, insert `Selected` component, set primary
     - `deselect(&mut self, world: &mut World, entity: Entity)` — remove from set, remove `Selected` component, update primary if needed
     - `clear(&mut self, world: &mut World)` — iterate all, remove components, clear set, clear primary
     - `replace(&mut self, world: &mut World, entity: Entity)` — clear + select
     - `is_empty(&self) -> bool`
     - `count(&self) -> usize`
     - `handle_picking_result(&mut self, world: &mut World, entity: Option<Entity>)` — if Some, replace-select; if None, clear
   - `#[cfg(test)] mod tests` — unit tests for all methods

**Key Implementation Decisions:**
- `world.insert_one(entity, Selected)` silently no-ops if entity was already selected (HashSet prevents duplicate)
- `world.remove_one::<Selected>(entity)` returns `Result` — unwrap or ignore errors (entity may have been despawned)
- `primary` defaults to `None`, updated on `select()` to the newly-selected entity, updated on `deselect()` to first remaining if primary was removed
- No `Default` derive (manual `new()`) since `HashSet` needs `new()`

**Dependencies:** Step 1 (Selected component in ecs/components.rs)

**Verification:**
```bash
cargo test  # will run SelectionManager unit tests
cargo check
```

**Pitfalls:**
- Entity may have been despawned outside SelectionManager — `remove_one` may error; use `.ok()` to ignore
- HashSet iteration order is non-deterministic — don't rely on it for `primary` fallback
- `Selected` component must NOT be added to entities that are not in `selected` set — invariant: `selected.len() == query::<With<Selected>>().count()`

**Exit Criteria:**
- [ ] `cargo check` passes
- [ ] `cargo test` — all SelectionManager unit tests pass
- [ ] `select()` adds to set AND inserts component

- [ ] `clear()` removes all components and clears set

### Step 3 — GPU Picking Pass

**Goal:** Implement `PickingPass` — offscreen `Rgba32Uint` texture, entity ID-encoded fragment shader, two-phase async readback (request frame N, resolve frame N+1), entity-to-instance-index mapping regeneration.

**Context Brief:**

The picking pass is the most technically challenging subsystem. It renders all `Renderable` entities to an offscreen `Rgba32Uint` texture where each fragment's color encodes the entity's instance index as a flat u32. On the next frame, the CPU reads back the pixel under the cursor and decodes it back to an entity handle via a `Vec<hecs::Entity>` mapping.

**Two-phase protocol:**
- Frame N (click): `request_pick_at(screen_coords)` — stores pending coords
- Frame N+1 (render): picking pass renders entity IDs to texture, copies to staging buffer
- Frame N+1 (resolve): `resolve_pick()` maps staging buffer, reads u32, decodes via mapping, returns `Option<Entity>`

**Picking WGSL shader** (§spec §5.2):
```wgsl
// Vertex: pass instance_index as @interpolate(flat) entity_id
// Fragment: return vec4<u32>(in.entity_id, 0u, 0u, 0xFFFFFFFFu)
```

**Task List:**

1. **Implement `src/selection/picking.rs`:**
   - `PickingPass` struct with all fields from spec §5.2:
     - `texture: wgpu::Texture` — `Rgba32Uint`, size = viewport
     - `view: wgpu::TextureView`
     - `bind_group: wgpu::BindGroup` — camera uniform
     - `pipeline: wgpu::RenderPipeline` — using `picking.wgsl`
     - `staging_buffer: wgpu::Buffer` — `MapMode::Read`, `COPY_DST`
     - `pending_result: Option<(u32, u32)>` — screen coords
     - `last_entity: Option<hecs::Entity>`
     - `mapping: Vec<hecs::Entity>` — instance index → entity handle

2. **Implement `PickingPass::new(device, config, camera_bind_group_layout, viewport_size)`**:
   - Create `Rgba32Uint` texture with matching dimensions
   - Load `picking.wgsl` via `include_str!()`
   - Create render pipeline with `wgpu::PrimitiveTopology::PointList` or reuse entity vertex buffers (for pixel-perfect picking, use same vertex data as entity renderer — simplest approach: reuse the entity vertex buffers and draw with picking pipeline)
   - Create staging buffer: 4 bytes (single pixel), `MapMode::Read`

3. **Implement `PickingPass::request_pick_at(&mut self, screen: (u32, u32))**`:
   - Store `self.pending_result = Some(screen)`

4. **Implement `PickingPass::render(&mut self, encoder, world, camera_bind_group, camera_buffer)`**:
   - Only execute if `pending_result.is_some()`
   - Regenerate `self.mapping` from ECS: query all entities with `Renderable`, collect into Vec
   - Render picking pass: clear texture to `(0xFFFFFFFF, 0, 0, 0xFF)` (sentinel for "no hit"), draw entities with picking pipeline
   - Copy pixel at `pending_result` location to staging buffer via `encoder.copy_texture_to_buffer()`

5. **Implement `PickingPass::resolve_pick(&mut self, device, queue) -> Option<Entity>`**:
   - If `pending_result.is_some()`:
     - Map staging buffer (`device.poll(Maintain::Wait)`)
     - Read u32 value
     - If u32 < mapping.len() → return mapping[u32]
     - If u32 == sentinel (0xFFFFFFFF) → return None
     - Unmap
   - `self.pending_result = None`
   - Return result

6. **Implement ** `PickingPass::resize(&mut self, device, new_size)`** — recreate texture + view at new dimensions.

**Key Implementation Decisions:**
- Picking pass only renders when `pending_result.is_some()` — not every frame
- The `mapping` is regenerated each time picking renders, not cached across frames (avoids stale entity handles)
- Instance index 0xFFFFFFFF is the sentinel for "no entity" (clear color)
- Use `device.poll(Maintain::Wait)` with a short timeout (1-2 frame periods) — if it times out, return None for that frame
- The picking pipeline can share vertex buffers with the entity renderer (same vertex data), just with a different pipeline that outputs u32

**Dependencies:** Step 2 (SelectionManager), Step 1 (picking.wgsl stub now needs implementation)

**Verification:**
```bash
cargo check
```
Full verification requires the app loop (Step 15). Compile-time is primary.

**Pitfalls:**
- `Rgba32Uint` texture format requires `TEXTURE_BINDING | RENDER_ATTACHMENT | COPY_SRC` usage flags
- Staging buffer must be 4 bytes minimum; map size must match buffer size
- `copy_texture_to_buffer` uses `wgpu::ImageDataLayout { bytes_per_row: Some(4), rows_per_image: Some(1) }`
- Device polling with timeout can stall the render loop if GPU is slow — keep timeout short (~16ms = 1 frame)
- `device.poll(Maintain::Wait)` blocks — use `Maintain::Wait` with `wgpu::PollType::Wait` for simplicity in v0.2.0; optimize with timeout in v0.3.0

**Exit Criteria:**
- [ ] `cargo check` passes
- [ ] `PickingPass` struct compiles with all wgpu types
- [ ] `picking.wgsl` shader implemented with flat u32 entity_id output
- [ ] Two-phase request/render/resolve protocol compiles
- [ ] Staging buffer readback logic handles sentinel case
- [ ] `resize()` method recreates texture at new dimensions

### Step 4 — Spatial Index (rstar)

**Goal:** Implement `SpatialIndex` — rstar R-tree wrapper with `SpatialEntry`, `RTreeObject` + `PointDistance` trait implementations, insert/remove/nearest_neighbor/enclosed_in/intersecting/rebuild methods, and lazy dirty tracking.

**Context Brief:**

The spatial index wraps the `rstar::RTree<SpatialEntry>` for spatial queries used by snap engine (nearest neighbor) and window selection (range queries). It uses lazy rebuild: after entity modifications, `dirty` is set to `true`; before the next snap or window query, if `dirty`, the tree is rebuilt from ECS state.

`SpatialEntry` holds `entity: hecs::Entity` and `bounds: BoundingBox2D`. It implements `RTreeObject` (envelope from bounds) and `PointDistance` (delegates to envelope). `PartialEq` is derived on entity only — two entries with the same entity are considered equal, enabling `remove_with_selection_function`.

**Task List:**

1. **Implement `src/spatial/mod.rs`:**
   ```rust
   pub struct SpatialIndex {
       pub tree: RTree<SpatialEntry>,
       pub dirty: bool,
   }
   ```

2. **Implement `SpatialEntry`** — `#[derive(Debug, Clone, PartialEq)]` (PartialEq on entity only), with `entity: hecs::Entity`, `bounds: BoundingBox2D`.

3. **Implement `RTreeObject for SpatialEntry`** — `Envelope = AABB<[f64; 2]>`, `envelope()` from `bounds`.

4. **Implement `PointDistance for SpatialEntry`** — `distance_2()` and `contains_point()` delegate to envelope.

5. **Implement `SpatialIndex` methods:**
   - `new()` — empty RTree, `dirty: false`
   - `insert(entity, bounds)` — insert entry into tree; set dirty = false after
   - `remove(entity)` — `remove_with_selection_function(|e| e.entity == entity)`
   - `nearest_neighbor(point: Point2D) -> Option<Entity>` — unwrap entry
   - `enclosed_in(rect: &BoundingBox2D) -> Vec<Entity>` — `locate_in_envelope` (strictly inside)
   - `intersecting(rect: &BoundingBox2D) -> Vec<Entity>` — `locate_in_envelope_intersecting` (overlap)
   - `rebuild(world: &World)` — bulk-load all entities with their bounding boxes
   - `ensure_clean(world: &World)` — if dirty, call rebuild; used by snap/window query callers

6. **`#[cfg(test)] mod tests`** — Unit tests for insert, remove, nearest, enclosed_in, intersecting, rebuild.

**Key Implementation Decisions:**
- `PartialEq` on `SpatialEntry` compares entity only — this is intentional for `remove_with_selection_function` (Rev 10 H5 confirmed this design)
- Lazy rebuild: `ensure_clean()` is called at the start of every query method
- `nearest_neighbor` returns `Option<Entity>` — caller must handle empty tree
- `rstar::RTree` does not have a built-in "dirty" flag — we maintain it ourselves

**Dependencies:** Step 1 (rstar crate, BoundingBox2D from geometry)

**Verification:**
```bash

cargo check
```

**Pitfalls:**
- `rstar::RTree::bulk_load()` requires `Vec<SpatialEntry>` — for large draws, this allocation is fine for v0.2.0
- `remove_with_selection_function` removes ALL matching entries — since PartialEq compares entity only, and entity handles are unique, this is correct
- `AABB::from_corners` expects `[f64; 2]` arrays — convert from `Point2D` fields explicitly
- `locate_in_envelope` returns items STRICTLY inside; `locate_in_envelope_intersecting` returns items that overlap — correct for enclosing vs crossing semantics

### Step 5 — Window Selection

**Goal:** Implement `WindowSelectState`, `WindowSelectMode` (Crossing/Enclosing), mode-from-drag-direction logic, and spatial query dispatch. This is the logic-only layer; the renderer comes in Step 13.

**Context Brief:**

Window selection is triggered when the user left-clicks and drags with no active command. The drag direction determines the mode:
- **Left-to-right (screen x increases):** Enclosing (blue) — selects only entities fully inside the rectangle
- **Right-to-left (screen x decreases):** Crossing (green) — selects entities intersecting the rectangle

The `WindowSelectState` stores `start, current: Point2D` in **world coordinates** and `mode: WindowSelectMode`. The `query()` method calls the spatial index with the computed bounding rectangle.

**Task List:**

1. **Implement `src/selection/window_select.rs`:**
   - `WindowSelectMode` enum: `Crossing`, `Enclosing` — with `Debug, Clone, Copy, PartialEq`
   - `WindowSelectState` struct: `pub start: Point2D, pub current: Point2D, pub mode: WindowSelectMode`
   - `impl WindowSelectState`:
     - `new(start, current) -> Self` — defaults mode to Enclosing (updated on release)
     - `mode_from_drag(start_screen, current_screen) -> WindowSelectMode` — compare x values
     - `query(&self, spatial: &SpatialIndex) -> Vec<Entity>` — compute unified rect, dispatch to `enclosed_in` or `intersecting`

2. **`#[cfg(test)] mod tests`** — Test mode determination and query dispatch.

**Key Implementation Decisions:**
- `start`/`current` stored in world coordinates (allows consistent rect computation regardless of camera)
- Mode determined at drag END (mouse release) using screen coordinates — stored as field for renderer to display correct color during drag
- The unified rect normalizes min/max regardless of drag direction for spatial query

**Dependencies:** Step 2 (SelectionManager), Step 4 (SpatialIndex)

**Verification:**
```bash

cargo check
```

**Pitfalls:**
- Mode is determined at drag END, but the renderer needs to show the rectangle DURING drag — store mode tentatively as Enclosing and update on release
- World coordinates during drag may shift if camera moves — for v0.2.0, camera movement during window select is disallowed (defer to v0.3.0)

**Exit Criteria:**

### Step 6 — Snap Engine Core

**Goal:** Implement `SnapEngine` — snap types enum, config, `SnapResult` struct, and the main `snap()` pipeline that generates candidates from spatial index nearest neighbors, filters by tolerance, ranks by priority, and returns the best match or raw point.

**Context Brief:**

The snap pipeline runs every frame on mouse move:
1. Query spatial index for nearest neighbor within aperture radius
2. For that entity, generate snap candidates based on active snap types
3. Filter candidates by screen-space distance < `aperture_size`
4. Rank by snap type priority (configurable per-type)
5. Return best match, or raw point if no candidate passes all filters

`SnapEngine` holds `active_types: Vec<SnapType>` (which snap types are enabled), `config: SnapConfig`, and `last_result: Option<SnapResult>` (for visual feedback renderer).

Priority ranking: lower priority value = higher priority. Default priorities (from spec):
- Endpoint: 0 (highest)
- Midpoint: 1
- Center: 2
- Grid: 3
- Perpendicular: 4
- Tangent: 5
- Nearest: 6 (lowest)

**Task List:**

1. **Implement `src/snap/mod.rs`:**
   - `SnapType` enum with all 7 variants: `Endpoint, Midpoint, Center, Nearest, Perpendicular, Tangent, Grid` — `#[derive(Debug, Clone, Copy, PartialEq, Eq)]`
   - `SnapConfig` struct: `enabled: bool`, `marker_size: f32`, `aperture_size: f32`, `priority_map: HashMap<SnapType, u8>` — with `Default` impl setting all defaults

### Step 9 — History Stack & Transaction

**Goal:** Implement `History` struct — undo/redo stacks as `VecDeque<Transaction>`, `Transaction` with `label: String` and `ops: Vec<AtomicOp>`, `AtomicOp` enum with all typed variants (SpawnLine, DespawnLine, SetLineData, etc.), and `push()`/`undo()`/`redo()` methods.

**Context Brief:**

The History module is the foundation for undo/redo. Key design:
- `History` owns `undo_stack: VecDeque<Transaction>` and `redo_stack: VecDeque<Transaction>` — both grow forward (newest at back)
- `push(tx)` — pushes to undo_stack, **clears redo_stack** (standard undo/redo behavior), optionally enforces `max_depth`
- `undo(world)` — pops from undo_stack, applies ops in REVERSE, returns label, pushes to redo_stack
- `redo(world)` — pops from redo_stack, applies ops in ORDER, returns label, pushes to undo_stack
- `max_depth: Option<usize>` — `None` = unlimited; default 1000
- `entity_map: EntityMapping` — tracks old→new entity handle mapping during undo/redo

**AtomicOp variants (§8.1):**
```rust
pub enum AtomicOp {
    SpawnLine { entity: Entity, data: LineData },
    SpawnCircle { entity: Entity, data: CircleData },
    SpawnArc { entity: Entity, data: ArcData },
    SpawnPolyline { entity: Entity, data: PolylineData },
    DespawnLine { entity: Entity, data: LineData },
    DespawnCircle { entity: Entity, data: CircleData },
    DespawnArc { entity: Entity, data: ArcData },
    DespawnPolyline { entity: Entity, data: PolylineData },
    SetLineData { entity: Entity, old: LineData, new: LineData },
    SetCircleData { entity: Entity, old: CircleData, new: CircleData },
    SetArcData { entity: Entity, old: ArcData, new: ArcData },
    SetPolylineData { entity: Entity, old: PolylineData, new: PolylineData },
    SetPosition { entity: Entity, old: Position, new: Position },
}
```

**Undo semantics:**
- `SpawnLine` → despawns entity
- `DespawnLine` → re-spawns entity with same data (creates new Entity handle, records mapping)
- `SetLineData` → restores `old` value
- Same pattern for Circle, Arc, Polyline, Position

**Context Brief:**

**Selection highlight (§10.1):** The entity shader (`entity.wgsl`) is updated to accept a per-instance `is_selected: u32` attribute. When `is_selected == 1u`, the fragment shader mixes `mix(color, vec4<f32>(0.0, 0.588, 1.0, 1.0), 0.3)` to produce the selection blue tint.

**Vertex format change:**
```rust
#[repr(C)]
struct EntityVertex {
    position: [f32; 2],
    color: [f32; 4],

}
```

## Anti-Pattern Checklist

| Anti-Pattern | Where It Bites | Guard |
|--------------|---------------|-------|
| **Stale entity handles after undo** | History, Selection, Spatial | Always consume `EntityMapping` after undo/redo and call `apply_entity_remapping()` |
| **Synchronous GPU readback stall** | Picking pass | Two-phase protocol: request on click, resolve next frame. Never block rendering on readback. |
| **Spatial index out of sync** | After modify commands | Use lazy rebuild via `dirty` flag; call `ensure_clean()` before every query |
| **Entity marker / HashSet desync** | Selection Manager | Every `select()` must insert `Selected` component; every `deselect()` must remove it. Unit test this invariant. |
| **NaN from degenerate geometry** | Snap candidates (perp/tangent/nearest) | Guard against zero-length segments, zero-radius circles, coincident points |
| **History memory leak** | Undo stack unbounded growth | Enforce `max_depth` (default 1000); pop oldest when exceeded |
| **Camera move during window select** | Window select + input | Lock camera during window select drag (defer camera-controlduring-select to v0.3.0) |
| **egui keyboard conflict** | Undo/redo shortcuts | Don't process Ctrl+Z/Y if `egui_ctx.wants_keyboard_input()` |
| **Selection on re-spawned entity** | After COPY command | Select the NEW entity (returned from spawn), not the old one |
| **Per-instance attribute format mismatch** | Entity renderer + vertex buffer | Verify `wgpu::VertexAttribute` offsets match `#[repr(C)]` struct layout exactly |
