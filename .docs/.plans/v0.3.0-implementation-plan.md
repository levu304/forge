# Forge v0.3.0 Implementation Plan

> **Organization — The Layered Canvas**  
> *Layer system, block definitions/insertions, property inheritance, advanced draw commands, and grip editing atop the v0.2.0 editing foundation.*  
> *Architecture review verdict: GO (Rev 18, 2026-05-28)*

---

## Plan Overview

**Objective:** Add layer system (create/rename/delete/reorder with per-layer color/linetype/linewidth/visibility/lock/freeze), entity-to-layer assignment with ByLayer/ByBlock/explicit property inheritance, block system (definitions, inserts, editor, explode), property palette (live read/write editing via egui), match properties, advanced draw commands (RECTANGLE, POLYGON, ELLIPSE, SPLINE), grip editing (interactive drag handles), multi-select modifier keys (Ctrl+click), and corresponding rendering/UI updates on the v0.2.0 ECS+wgpu+undo foundation.

### Step 2 — ECS Components & Resources, Transform2D, Spline Geometry

**Goal:** Fully implement the v0.3.0 ECS components (`LayerRef`, `PropertySource`, `PropertyValue<T>`, `BlockRef`), ECS resources (`LayerTable` stub, `BlockTable` stub), `Transform2D` with `apply_to_point()` and `apply_to_bounds()`, `CubicBezier` curve with `evaluate()` and `to_polyline()`, and `BoundingBox2D::empty()`/`from_points()` helper methods.

**Context Brief:**

Spec §5.2 defines `LayerRef(pub LayerId)` with a default to `LayerId::DEFAULT` (0). §5.3 defines `PropertySource` with three `PropertyValue<T>` fields (`color`, `linewidth`, `linetype`) and a manual `Default` impl that returns `ByLayer` for any `T`. §6.2 defines `BlockRef { definition: BlockId, transform: Transform2D }` with a `Position` component compatibility note. §6.2 defines `Transform2D` with `position: Point2D`, `scale: Point2D`, `rotation_degrees: f64`, and the composition order: scale → rotate → translate.

§6.2.1 defines `BlockTable` and `BlockId` (§8.5). Spec §8.4 defines `CubicBezier` with 4 control points, `evaluate(t)` using Bernstein basis, and `to_polyline(segments)` for flattening. Spec §6.1 requires `BoundingBox2D::empty()` and `BoundingBox2D::from_points()`.

`BlockEntity` enum (§6.1) stores serialized entity data within block definitions — not ECS components but a parallel data structure.

**Task List:**

1. **Implement `src/ecs/resources.rs`:**
   - Add `pub use crate::layer::table::LayerTable;` re-export (or define stub if layer module not yet implemented)
   - Add `pub use crate::block::definition::BlockTable;` re-export

2. **Implement `src/ecs/components.rs`:**
   - `LayerRef(pub LayerId)` with `Default` impl → `LayerId::DEFAULT`
   - `PropertyValue<T>` enum: `ByLayer`, `ByBlock`, `Explicit(T)` — manual `Default` impl returns `ByLayer`
   - `PropertySource` struct: `pub color: PropertyValue<Color>`, `pub linewidth: PropertyValue<f32>`, `pub linetype: PropertyValue<Linetype>` — derive `Default`, `Clone`, `Copy`, `Debug`, `Component`
   - `BlockRef` struct: `pub definition: BlockId`, `pub transform: Transform2D` — `#[derive(Debug, Clone, Copy, Component)]`
   - `BlockId(pub u32)` — `#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]`

3. **Implement `src/geometry/transform.rs`:**
   - `Transform2D` struct: `pub position: Point2D`, `pub scale: Point2D`, `pub rotation_degrees: f64`
   - `Transform2D::IDENTITY` constant: position=(0,0), scale=(1,1), rotation=0
   - `apply_to_point(&self, p: Point2D) -> Point2D`: scale → rotate → translate
   - `apply_to_bounds(&self, bounds: &BoundingBox2D) -> BoundingBox2D`: transform 4 corners, compute new AABB

4. **Implement `src/geometry/spline.rs`:**
   - `CubicBezier` struct: `p0, p1, p2, p3: Point2D`
   - `evaluate(&self, t: f64) -> Point2D`: `P(t) = (1-t)³·P0 + 3(1-t)²t·P1 + 3(1-t)t²·P2 + t³·P3`
   - `to_polyline(&self, segments: usize) -> Vec<Point2D>`: sample at `0, 1/N, 2/N, ..., 1`

5. **Add `BoundingBox2D` helpers** to `src/geometry/bounds.rs`:
   - `empty() -> Self`: min=(f64::MAX, f64::MAX), max=(f64::MIN, f64::MIN)
   - `from_points(points: &[Point2D]) -> Self`: compute union AABB
   - `union(&self, other: &BoundingBox2D) -> BoundingBox2D`: combine two bounds

6. **`#[cfg(test)] mod tests`** per file:
   - Transform2D: identity preserves point, scale (2x) works, rotation 90° maps (1,0)→(0,1), apply_to_bounds
   - CubicBezier: evaluate at t=0 returns p0, t=1 returns p3, to_polyline(0) returns 2 points
   - BoundingBox2D: empty→from_points round trip, union
   - PropertyValue: default is ByLayer, Explicit wraps value

### Step 3 — Layer System: Table, Manager, Linetype

**Goal:** Implement `LayerId`, `Layer` struct, `Linetype` enum, `LayerTable` (insert, delete, rename, get, get_by_name), `LayerManager` (delete_layer with reference counting), and `LayerError` types. Full CRUD with duplicate-name rejection and default layer protection.

**Context Brief:**

Spec §5.1 defines the layer model. `LayerId(pub u32)` is a newtype with `DEFAULT = LayerId(0)`. `Layer` struct has `id`, `name`, `color` (Color), `linetype` (Linetype), `linewidth` (f32), `visible` (bool), `locked` (bool), `frozen` (bool).

`LayerTable` manages layers via `HashMap<LayerId, Layer>` + `HashMap<String, LayerId>` for name lookups. Key methods: `insert()` (auto-assigns id, rejects duplicate names), `delete()` (rejects default layer, checks reference count), `rename()` (rejects duplicate names), `get()`, `get_by_name()`. `active_layer: LayerId` tracks the current layer for new entities.

`LayerManager` wraps `LayerTable` and provides `delete_layer(world, id)` that queries the ECS for `LayerRef` references before calling `table.delete()`.

`Linetype` enum (§5.1): `Solid`, `Dashed`, `Dot`, `DotDash`, `Border`, `Center`. Border and Center are defined but fall back to Solid in v0.3.0.

**Task List:**

1. **Implement `src/layer/layer.rs`:**
   - `LayerId(pub u32)` — `#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]`
   - `LayerId::DEFAULT = LayerId(0)`
   - `Layer` struct with all fields from spec §5.1 — `#[derive(Debug, Clone)]`
   - `Linetype` enum with 6 variants — `#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]`, default = `Solid`
   - `impl From<Linetype> for u32` for shader usage (Solid=0, Dashed=1, Dot=2, DotDash=3, Border=4, Center=5)

2. **Implement `src/layer/table.rs`:**
   - `LayerTable` struct: `layers: HashMap<LayerId, Layer>`, `name_to_id: HashMap<String, LayerId>`, `next_id: u32`, `active_layer: LayerId`
   - `new()` — creates default layer "0" with WHITE color
   - `insert(layer: Layer) -> Result<LayerId, LayerError>` — auto-assigns `LayerId(self.next_id)`, rejects duplicate names
   - `delete(id, number_of_references: usize) -> Result<(), LayerError>` — rejects default, rejects if references>0
   - `rename(id, new_name: String) -> Result<(), LayerError>` — reject duplicate names, not-found
   - `get(id) -> Option<&Layer>`
   - `get_by_name(name) -> Option<&Layer>`

3. **Implement `src/layer/mod.rs`:**
   - `LayerManager` struct: `pub table: LayerTable`
   - `new() -> Self`
   - `delete_layer(world: &hecs::World, id: LayerId) -> Result<(), LayerError>` — counts ECS `LayerRef` references, delegates to `table.delete()`

4. **`#[cfg(test)] mod tests`:**
   - Insert layer, verify id assigned
   - Insert duplicate name → NameExists
   - Delete default layer → CannotDeleteDefault
   - Rename to existing name → NameExists
   - get/get_by_name round-trip
   - LayerManager::delete_layer with 0 references succeeds
   - Linetype→u32 mapping correct

**Dependencies:** Step 1 (file structure), Step 2 (Color type, LayerRef component defined but used at runtime only)


### Step 4 — Property System: Resolver, Palette, MatchProperties

**Goal:** Implement `PropertyResolver` (3 resolve methods for color/linewidth/linetype + 3 direct methods for BlockEntity fields), `PropertyPalette` (egui-based entity property editor), and `match_properties()` (copy attributes between entities). All mutations recorded as Transactions for undo/redo.

**Context Brief:**

Spec §5.4 defines `PropertyResolver` with three pairs of methods:
- `resolve_color/linewidth/linetype(world, layer_table, entity, parent_block_ref)` — ECS query-based resolution following ByLayer → Explicit → ByBlock priority chain
- `resolve_color/linewidth/linetype_direct(source, layer_ref, layer_table, parent_block_ref)` — field-value-based resolution for `BlockEntity` data (not in ECS)

ByBlock resolution walks up to the parent `BlockRef` entity (single-level). If `parent_block_ref` is None, ByBlock falls through to ByLayer (§5.4 known limitation).

Spec §7.1 defines `PropertyPalette` with `draw()` rendering an egui SidePanel. It inspects `SelectionManager.primary`, shows entity type, layer dropdown, color picker, linewidth slider. All mutations capture old state and build `AtomicOp::SetLayerRef`/`SetPropertySource` Transactions.

Spec §7.2 defines `match_properties()` that copies `PropertySource` and `LayerRef` from source entity to all target entities, building a single Transaction.

Spec §5.4 defines `ResolvedProperties` caching type: `{ color, linewidth, linetype }` stored in a `HashMap<Entity, ResolvedProperties>` on ForgeApp, invalidated on undo/redo, PropertySource mutation, or LayerTable mutation.

**Task List:**

1. **Implement `src/property/resolver.rs`:**
   - `ResolvedProperties` struct: `pub color: Color`, `pub linewidth: f32`, `pub linetype: Linetype` — `#[derive(Debug, Clone, Copy)]`
   - `PropertyResolver` struct (no fields, just a namespace)
   - `impl PropertyResolver`:
     - `resolve_color(world, layer_table, entity, parent_block_ref) -> Color` — ByLayer→layer color, Explicit→value, ByBlock→recurse to parent or fallback
     - `resolve_linewidth(world, layer_table, entity, parent_block_ref) -> f32`
     - `resolve_linetype(world, layer_table, entity, parent_block_ref) -> Linetype`
     - `resolve_color_direct(source, layer_ref, layer_table, parent_block_ref) -> Color` — for BlockEntity field values
     - `resolve_linewidth_direct(source, layer_ref, layer_table, parent_block_ref) -> f32`
     - `resolve_linetype_direct(source, layer_ref, layer_table, parent_block_ref) -> Linetype`
   - Direct methods: v0.3.0 simplifies ByBlock → falls through to ByLayer. Full ByBlock resolution deferred to v0.3.1.

2. **Implement `src/property/palette.rs`:**
   - `PropertyPalette` struct (no fields)

### Step 10 — LinetypeRenderer Pipeline + Shader

**Goal:** Implement `LinetypeRenderer` — dedicated wgpu pipeline using a separate `LinetypeVertex` format (32 bytes: position + color + linetype + linetype_scale). Implement screen-space stipple WGSL shader with bitmask patterns. Entities with non-Solid linetype are rendered through this pipeline instead of EntityRenderer.

**Context Brief:**

Spec §10.1 defines `LinetypeRenderer` with its own vertex format (independent of EntityVertex):
```rust
struct LinetypeVertex {
    position: [f32; 2],     // offset 0
    color: [f32; 4],        // offset 8
    linetype: u32,          // offset 24
    linetype_scale: f32,    // offset 28
    // Total: 32 bytes, 0x20
}
```

`array_stride = 32`, topology = `LineList`.

Spec §10.2 defines `linetype.wgsl` — stipple patterns via bitmask lookup:
- 0xFFFF = Solid, 0x3333 = Dotted, 0x0F0F = Dashed, 0x1B1B = Dash-dot, 0xAAAA = Border, 0xCCCC = Center
- Screen-space pattern: `pattern_coord = dot(frag_coord, line_deriv)` where `line_deriv = normalize(dpdx + dpdy)`
- Pattern bit = `(pattern >> (u32(floor(pattern_coord / max(1, linetype_scale))) & 15)) & 1`
- `discard` if mask bit = 0

v0.3.0 limitations:
- Non-LineData entities (Circles, Arcs, Polylines) with non-Solid linetype fall back to Solid via EntityRenderer
- Border and Center linetypes are defined but fall back to Solid in shader
- Full deferred linetype resolution via PropertyResolver deferred to v0.3.1 — v0.3.0 uses flat world query

**Task List:**

1. **Implement `src/render/linetype_renderer.rs`:**
   - `LinetypeVertex` struct — `#[repr(C)]`, `bytemuck::Pod + Zeroable`
   - `LinetypeRenderer` struct: `pipeline`, `vertex_buffer`, `index_buffer`, `num_indices`
   - `new(device, config, camera_bind_group_layout) -> Self`:
     - Create pipeline layout with camera bind group
     - Create vertex buffer layout: stride=32, 4 attributes
     - Create render pipeline with `LineList` topology, `ALPHA_BLENDING`
     - Create placeholder buffers (1024 bytes each, COPY_DST)
   - `render(encoder, view, world, camera_uniform, camera_bind_group)`:
     - Query entities with non-Solid linetype (flat query — v0.3.0 limitation)
     - For each matching entity: extract vertices as `LinetypeVertex`, upload to GPU, draw indexed
     - Render pass: `LoadOp::Load` (draws on top of entity pass)

2. **Implement `src/render/shaders/linetype.wgsl`:**
   - `CameraUniform` bind group at group(0) binding(0)
   - `VertexInput`: position(vec2f), color(vec4f), linetype(u32), linetype_scale(f32)
   - `VertexOutput`: clip_position, color, linetype (flat), linetype_scale (flat)
   - `linetype_pattern(linetype: u32) -> u32`: switch on 0-5, return bitmask
   - Fragment main: compute screen-space stipple via derivative-based pattern coord, discard on 0 bit
   - Use `floor(in.clip_position.x), floor(in.clip_position.y)` for frag_coord

### Step 11 — BlockRenderer + GripRenderer

**Pitfalls:**
- `property_cache` is a `HashMap<hecs::Entity, ResolvedProperties>` on `ForgeApp`. It's NOT part of the ECS. It must be manually invalidated whenever property sources, layer properties, or entity-layer assignments change.
- Block editor render mode: when editing a block, the viewport shows ONLY block def entities. The main drawing entities are hidden. This requires a mode switch in the entity renderer's vertex collection.
- Grip drag with undo: the `GripDragState::snapshot` is stored as an `Option<AtomicOp>`. At drag end, `finalize_transaction()` updates the `new` field. If Ctrl+Z is pressed during drag, the drag is cancelled and the snapshot is discarded (entity snaps back to start_position via the pre-drag state already being applied in-world).
- `CommandResult::CompleteWithTransaction` handler must NOT push duplicate transactions. Ensure that commands returning this variant do NOT also apply mutations directly in the command (they should only spawn entities and build the transaction).
- Selecting entities on locked layers: v0.3.0 does NOT block selection of locked-layer entities (the v0.2.0 selection system has no layer awareness). This is a known limitation — layer lock only prevents modification via the grip system (grips are not generated for locked-layer entities).
- `SpatialIndex::rebuild()` now takes `&BlockTable` — all rebuild calls in ForgeApp must be updated.

## Anti-Pattern Checklist

| Anti-Pattern | Where It Bites | Guard |
|--------------|---------------|-------|
| **Stale entity handles after undo/redo** | Selection, Spatial, Property cache | `apply_entity_remapping()` must be called after every undo/redo; `property_cache` must be cleared |
| **Property cache stale** | Render loop — shows wrong color/width | Invalidate cache on PropertySource change, LayerRef change, LayerTable modification, and every undo/redo |
| **ByBlock infinite recursion** | PropertyResolver with nested blocks | Single-level only in v0.3.0: recurse once, then fall through to ByLayer. Guard with recursion counter or explicit single-hop. |
| **Layer delete with active entities** | LayerTable::delete() | `LayerManager::delete_layer()` queries ECS for `LayerRef` references. The count parameter prevents silent deletion. |
| **Block editor clone memory** | BlockEditorState::enter() for 10k+ entities | Acceptable for v0.3.0. Document as O(n) allocation; optimization deferred to v0.4.0. |
| **Grip position drift after undo** | Grip drag + undo/redo cycle | `GripDragState::capture_snapshot()` captures pre-drag state as AtomicOp; `finalize_transaction()` completes it. Ctrl+Z during drag discards snapshot (entity snaps back). |
| **Linetype shader aliasing** | Screen-space stipple at low zoom | Add min-dash-length clamp in shader: `max(1.0, linetype_scale)` prevents sub-pixel patterns. |
| **Spatial index stale after block edit** | Block editor save → block bounds changed | After `BlockEditorState::save()`, mark `spatial_index.dirty = true`; rebuild on next query with `&block_table`. |
| **BlockRef Position / transform desync** | MOVE/ROTATE/SCALE on BlockRef entities | Modify commands update `Position` but NOT `BlockRef.transform`. Display drift is a known v0.3.0 limitation (documented in spec §6.2). |
| **BLOCK/INSERT toolbar buttons** | Clicked but no command handler | Dispatch falls through gracefully. Button label should indicate "v0.3.1" if UI space allows. |
| **`CommandResult::CompleteWithTransaction` match exhaustiveness** | ForgeApp dispatch misses the new variant | Every match on `CommandResult` must handle `CompleteWithTransaction`. Add `_ => unreachable!()` for safety. |
| **Frozen layer selection** | User can select entities on frozen layers | v0.3.0 does not block selection on frozen layers (only rendering culling respects freeze). Document as known limitation. |
| **Layer deletion undo not supported** | Layer Panel deletes directly, no Transaction | v0.3.0 layer CRUD is direct (no undo for layer creation/deletion/rename). Document as known limitation; Transaction-based layer undo deferred to v0.3.1. |
